# Parity harness plan

Reference: OpenRig v0.6.9 at `/home/box/research/openrig-port/openrig`, HEAD `bed4d45`. It has **1,513 TS test files and 367,916 lines** (vitest; daemon 250,745, cli 66,688, ui 36,233, tui 14,250).

Crate names follow Architect's design (`crewmux-*`); see `design/workspace-layout.md`.

## Three layers, cheapest first
1. **Ported unit tests (default).** Pure-logic TS tests (the wake ladder, the workflow, scope, review and slices engines, the classifiers, spec validation) are rewritten as Rust `#[test]`s. The TS test file is the spec, and no TS runtime is needed. Expected for slices 4, 5, 9 and 12, plus 14–19.
2. **Golden fixtures captured from TS.** Use these when the output is large or structured (CLI `--json` output, MCP tools/list, RigSpec validation errors, provider config writes, screen classification).
   - **Running TS:** `cd openrig && npm ci && npm run build -w packages/daemon` (node ≥ 20; the box has v20.19.2). vitest is per package: `npx vitest run <file>`.
   - **Capture:** a small vitest file per slice in `tests/parity/capture/<slice>.capture.test.ts` imports the TS module directly, feeds it inputs (often lifted from the existing TS test), and writes one JSON per case into `$FIXTURE_OUT`. Use `TZ=UTC`, a temp `OPENRIG_HOME`, and redact ULIDs, timestamps and paths at capture time.
   - **Format and location:** `tests/fixtures/sNN-<name>/<case>.json` (schema in `pr/tests/fixtures/README.md`), and raw pane captures in `.../captures/*.txt`.
   - **Regen:** `OPENRIG_DIR=… scripts/regen-fixtures.sh sNN-<name>` refuses to run unless openrig is at the pinned commit. Diffs are reviewed like code, and `expect` is never hand-edited.
   - **Rust side:** a `crewmux-testkit` helper `parity::cases("s04-wake-ladder")` iterates the fixtures, and each crate's `tests/parity_sNN.rs` asserts `run(input) == expect` with an insta `assert_json_snapshot!` for readable diffs.
3. **Differential runner (only where state and timing matter).** Use it for the slice 1–4 daemon flows and the slice 6 MCP surface. A Rust test harness starts the TS daemon (`node packages/daemon/dist/index.js` with its own home and port) and `crewmux daemon run` (own `RIG_HOME`, UDS), drives the same scripted scenario against both with a stub runtime and private tmux sockets (`-L`), then compares the *normalised* observable output: CLI `--json`, event sequence, and tmux argv sequence recorded via a fake `TmuxExec`. It's gated behind the `differential` cargo feature (declared on each crate that needs it), the nextest test-name segment `::differential::`, and `OPENRIG_DIR`. It runs on demand and nightly, not per PR, because it needs node, npm ci and tmux. The fresh schema (ADR-0003) means DB rows are **not** compared, only API-visible behaviour.

## Marking ported and skipped tests
- `tests/parity/LEDGER.md` has one row per in-scope TS test file: `ported | partial | skipped | todo`, the Rust test path(s), and notes. The `guards` CI job fails if a `ported` row points at a path that doesn't exist.
- In Rust, every ported test starts with a doc comment: `/// ts: packages/daemon/test/queue-wake-ladder.test.ts > "escalates after 3 nudges"`. That makes `rg 'ts: '` the reverse index.
- A test whose TS case is intentionally not ported is **not** written as an `#[ignore]`. It gets a ledger row `skipped` with a reason (out of scope / TS-internal / fresh schema). `#[ignore = "…"]` is only for a temporarily broken port and must cite an issue (enforced by the guard).
- Slice "done" = every in-scope row for that slice is `ported` or `skipped` with a reason, and all parity tests are green.
