# ADR-0007: YAML library: serde-saphyr

Status: Accepted (2026-10-11).

## Context
- RigSpec and AgentSpec are YAML. OpenRig uses `yaml` (eemeli).
- Validation must report **line/column**.
- `serde_yaml` is archived/unmaintained, and its forks are uneven.

## Options
1. **serde-saphyr.** A serde front-end on the saphyr parser. Maintained, with spanned errors, and no unsafe-libyaml.
2. serde_yml / serde_norway (serde_yaml forks). Maintenance and provenance concerns.
3. yaml-rust2 plus a hand-mapped DOM. More code, but maximal control.

## Decision
- **serde-saphyr** is wrapped in **`crewmux-spec::yaml`**, the only module allowed to import it. That lets the backend be swapped without touching callers.
- Errors map to `SpecError { line, col, path, message }`.
  - Unknown keys and duplicate keys are rejected.
  - Seat names are restricted to `[A-Za-z0-9_-]` (slice 1, PR #9).
- **Comments are not preserved.** The port never rewrites user YAML. Snapshots and exports emit fresh YAML.
- YAML anchors and merge keys are accepted as the parser supports them. Specs that relied on OpenRig quirks are recorded in the ledger, not emulated.

## Consequences
- `spec_validate_rig` / `spec_validate_agent` (ADR-0002) return the same line/col the CLI prints.
- The diff harness compares validation messages after normalisation. Wording differences need a PE.

## Open risks
- serde-saphyr is young. It is pinned exactly, and the parser behaviour is golden-tested on the OpenRig fixture specs.
