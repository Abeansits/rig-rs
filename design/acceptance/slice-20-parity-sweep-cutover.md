## Scope
1. **Parity sweep and CLI inventory.**
   - Implement every remaining in-scope CLI verb and route that the contract inventory lists as "not yet ported".
     - The inventory is generated by a new `cargo xtask cli-inventory` from the v0.6.9 commander tree (~221 registrations) into `parity/cli-contract.md`.
     - Spike S12's inventory is not in the repo, and only spikes 1–10 are on the box.
     - Out-of-scope verbs are excluded per the porting map, each with a reason.
   - Close the ledger: no `todo` rows. Every row is `ported`, `reused`, `waived` (with a reason) or `diverged` (with a PE that exists).
   - All in-scope test-system scenarios pass on rig-rs: the v0.6.9 scenario YAMLs (21 at last count), minus out-of-scope ones.
2. **Error and help text pass.**
   - RigSpec and agent-spec validation messages, and `--help` for every verb.
   - Text that skills and docs quote must match TS or differ deliberately with a PE. PE-003 (help/version subset) is retired or narrowed here.
3. **Skills and docs.**
   - Shipped skills (embedded under `assets/skills/`, extracted by `rig setup`) keep the `rig` verbs.
   - MCP tool names follow ADR-0002 (repo PE-016; `cargo xtask lint mcp-legacy-names`).
   - "OpenRig" branding is removed except in attribution, and docs are trimmed to in-scope.
4. **Distribution (release-gated).** Nothing is published, tagged or released without Sebastian's explicit OK. This covers git tags, GitHub releases, uploaded artifacts, a Homebrew tap and crates.io. Config and dry-run work may proceed without it: cargo-dist config, `dist plan`/`dist build` locally or in CI without upload, and the release workflow in a mode that has no publish step.
   - One `rig` binary per target via cargo-dist. **G6 targets: macOS arm64, macOS x86_64 and Linux x86_64.**
   - `rig --version` with build info (version, commit, target).
   - A Homebrew tap only if Sebastian wants one, and only after his explicit OK.
   - No Node, no npm, no ABI checks.
   - The toolchain is the repo pin (1.99.0, `rust-version = "1.99"`).
5. **Licence and NOTICE audit (§11).**
   - LICENSE is Apache-2.0.
   - NOTICE credits OpenRig.
   - CHANGES.md is the prominent change statement.
   - `cargo xtask check-notices` covers 100% of derived files. This is the header check deferred in PR #1.
   - `cargo deny check licenses` is clean.
   - No use of the "OpenRig" name implying endorsement.
6. **Rename via `STATE_DIR_NAME` (G4).**
   - When Sebastian picks the product name, the state folder rename is a **one-line change** to `STATE_DIR_NAME`, plus `.rig-rs` appended to the legacy names, so setup symlinks the old placeholder.
   - The `.openrig` compat symlink never clobbers an existing directory, and doctor checks it.
   - Binary, product and docs names change in the same PR. Crate names (`crewmux-*`) change only if Sebastian asks.
7. **No Node import (G7).** Node OpenRig's DB, specs or state dir are never read or imported. The cutover starts from a fresh state dir.
8. **Dogfood and cutover runbook.**
   - A multi-session dogfood on Sebastian's real setup (QA Bot).
   - A runbook covering:
     - a fresh state dir (`~/<STATE_DIR_NAME>`), with the `.openrig` compat symlink created by setup (G4) and no import (G7);
     - running both side by side on separate tmux sockets during the transition;
     - rolling back to Node OpenRig.
